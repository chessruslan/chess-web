## Запрещено

1. Не менять схему подключения базы, URL базы, anon-ключ, Caddy, серверные папки или настройки Selectel без прямого разрешения пользователя.
2. Не выполнять для продакшена обычную команду `flutter build web` без `--dart-define`.
3. Не менять `PUBLISH_MAKECHESS.cmd` без прямого разрешения пользователя.
4. Не публиковать сайт напрямую через `scp`, `ssh`, ручную замену папок или собственный новый скрипт.
5. Не заменять рабочую версию сайта непроверенной сборкой.
6. Не возвращать прямое подключение к `*.supabase.co`.
7. Не удалять существующую логику проекта при точечных изменениях.

## Единственный разрешённый способ публикации

Публикация выполняется только файлом:

`PUBLISH_MAKECHESS.cmd`

Он обязан:

- собрать Flutter Web с правильными `SUPABASE_URL` и `SUPABASE_ANON_KEY`;
- проверить готовый `build/web/main.dart.js`;
- остановиться, если найден старый URL или старый ключ;
- проверить ответ базы `API_PRECHECK=200`;
- создать резервную копию работающего сайта;
- заменить сайт только после всех проверок;
- автоматически вернуть старую версию при неудачной серверной проверке.

## Правило работы Codex

Codex может читать проект, анализировать код, вносить согласованные хирургические правки и запускать локальные проверки. Публиковать сайт Codex может только после прямой команды пользователя и только через `PUBLISH_MAKECHESS.cmd`.

Перед изменением инфраструктурных файлов Codex обязан остановиться и объяснить пользователю простыми словами:

- какой файл планируется изменить;
- зачем это нужно;
- что останется неизменным;
- как будет выполнен откат.
